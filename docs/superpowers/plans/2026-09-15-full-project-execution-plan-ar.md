# خطة التنفيذ الكاملة لمنصة النعماني

> **للعاملين الآليين:** يجب تنفيذ هذه الخطة مهمةً مهمة باستخدام `superpowers:subagent-driven-development` أو `superpowers:executing-plans`. كل تغيير وظيفي يبدأ باختبار RED ثم أقل تنفيذ GREEN ثم Refactor، مع commit مستقل بعد نجاح التحقق.

**الهدف:** استكمال منصة النعماني بحيث تعمل الفروع والنوع والصلاحيات والمدفوعات والتقييمات والاشتراكات والتقارير والويبسايت كوحدات مترابطة وآمنة وقابلة للتدقيق.

**المعمارية:** يعمل النظام الحالي بـ NestJS + Prisma + MySQL في الـBackend وReact/Vite في لوحة الإدارة وVite/JavaScript في الويبسايت. ستظل فروع التشغيل الفعلية مستقلة للتسعير والاشتراك، بينما تربطها عائلة فرع قانونية للعضو والكود والصلاحيات والتقارير. الصلاحيات الحديثة RBAC هي المصدر الوحيد الفعّال، مع دور وظيفي أساس واستثناءات Allow/Deny لكل مستخدم.

**التقنيات:** NestJS 11، Prisma 5، MySQL، React 18، TypeScript، Vite، Jest، Node Test Runner، Git/GitHub.

**المواصفة المرجعية:** `docs/superpowers/specs/2026-09-15-platform-modernization.md`.

## قيود لا يجوز تجاوزها

- لا يتم تشغيل أي migration أو `prisma db push` أو seed أو reset على قاعدة البيانات الحية قبل نسخة احتياطية مجرّبة وقاعدة مستنسخة وموافقة تشغيلية.
- migrations إضافية وForward-only فقط؛ يمنع `DROP TABLE` و`DROP COLUMN` وعمليات فقد البيانات ضمن هذه الخطة.
- لا تثق أي خدمة بسعر قادم من الـFrontend؛ خدمة الـBackend تحل السعر الفعلي وتسجله Snapshot.
- لا تُكتب أرقام فروع أو أسماء مثل طنطا داخل المنطق؛ تُدار علاقة العائلة من البيانات بـ `canonical_branch_id`.
- بيانات التسويق/المتابعة التاريخية لا تُحذف؛ يزال إدخالها اليدوي من نموذج العضو فقط.
- لا تظهر صفحة أو رابط أو نتيجة بحث أو بطاقة Dashboard دون صلاحية `view` فعّالة.
- كل commit يمر على `git diff --check` وفحص الأسرار، ويُراجع قبل دمجه في `main`.
