# ONE80 QR gate update — 2026-09-20

## What changed

- Web member previews, prints and PNG clipboard/downloads encode the numeric gate credential as QR. The membership reference remains a separate readable label.
- QR management explicitly provisions missing credentials within the already-authorized page of members. Existing and disabled credentials are preserved.
- Flutter keeps the member reference separate from the gate credential, refreshes the authoritative profile on home load/pull-to-refresh, and retains the saved credential offline. Explicit revocation clears the cached QR. No phone/member ID fallback is allowed.
- QR payloads must survive the existing Wiegand-26 numeric path: canonical decimal values 1–16777215. Unsupported, absent and disabled credentials do not produce a pass.
- Both views provide black/white square QR with a four-module quiet zone. Flutter uses the existing barcode library; the web uses the existing qrcode.react dependency.
- Controller snapshots exclude inactive and unsupported credentials.
- The new receptionist check uses saved settings and the saved token without restarting the agent, synchronizing members or opening a door. A protected status endpoint supports authentication verification.
