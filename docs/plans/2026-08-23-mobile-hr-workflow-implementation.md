# تنفيذ تدفقات تطبيق الموظف — 2026-08-23

## الهدف

توحيد تدفقات الإجازات والأذونات والسلف في واجهة `/api/mobile` مع حالات الوارد/الصادر/المقبول/المرفوض، وإتاحة التقرير الطبي الاختياري للإجازة المرضية، وإحالة السلفة إلى مسؤول الموارد البشرية عند عدم وجود مدير مباشر.

## خطوات التنفيذ

1. كتابة اختبارات فاشلة لمسارات إجراءات الإجازة والإذن، وحقول الإجازة المرضية الاختيارية، وتحويل السلفة إلى الموارد البشرية.
2. إضافة مسارات إجراءات الإجازة والإذن وربط قوائمها بوضع العرض الصحيح مع الافتراضي `sader`.
3. تعديل إنشاء الإجازة من التطبيق لإلغاء فحص الرصيد وجعل التقرير الطبي حقلاً اختيارياً قابلاً للحفظ.
4. توسيع قوائم السلف بالحالات المطلوبة وإضافة تبويب الملغاة وتحويل السلفة بلا مدير مباشر إلى مسؤول الموارد البشرية.
5. تحديث عقد Flutter/API وتدقيقه، ثم تشغيل اختبارات النطاق وفحص TypeScript.

## قواعد العمل المؤكدة

- المقبول: `suspend in [1, 4]`.
- المرفوض: `suspend in [2, 5]`.
- الإجازة المرضية تظهر فيها واجهة رفع التقرير، لكن لا تمنع الإرسال من دونه.
- مدة الإذن في الطلب الواحد لا تتجاوز 120 دقيقة.
- لا يُفحص رصيد الإجازة عند إنشاء طلب من تطبيق الموظف الجديد.
